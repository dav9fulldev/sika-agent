# SIKA Full Engineering Review


## Step 1 — Architecture Analysis

Act as the Lead / Software Architect.

Analyze:

- Repository structure.
- Flutter application.
- FastAPI backend.
- Database architecture.
- Redis usage.
- API communication.
- Google Cloud infrastructure.
- CI/CD configuration.

Do not modify any file during this step.

Identify:

- Architecture strengths.
- Architecture weaknesses.
- Technical debt.
- Missing components.
- Potential risks.

Classify findings as:

- CRITICAL
- HIGH
- MEDIUM
- LOW

## Step 2 — UI/UX Review

Act as the UI/UX Engineer.

Analyze the Flutter application.

Review:

- Application structure.
- Screens.
- Navigation.
- Design consistency.
- Typography.
- Spacing.
- Cards.
- Colors.
- Buttons.
- Forms.
- Loading states.
- Error states.
- Empty states.
- Responsive behavior.

Do not modify files yet.

Provide a prioritized list of UI/UX improvements.

## Step 3 — QA Review

Act as the QA / Test Engineer.

Analyze:

- Existing tests.
- Missing tests.
- Critical user flows.
- API integration.
- Authentication flows.
- Error handling.
- Edge cases.

Identify the most important tests that should be implemented.

Do not modify production code.

## Step 4 — Security Review

Act as the Security Reviewer.

Review:

- Authentication.
- JWT implementation.
- Secret handling.
- Environment variables.
- API input validation.
- CORS.
- Logging.
- Database access.
- Redis usage.
- Google Cloud configuration.

Never display secret values.

Classify findings:

- CRITICAL
- HIGH
- MEDIUM
- LOW

## Step 5 — DevOps / Cloud Review

Act as the DevOps / Cloud Engineer.

Review:

- Docker configuration.
- Cloud Run configuration.
- Cloud SQL connectivity.
- Redis connectivity.
- Secret Manager integration.
- IAM permissions.
- CI/CD pipeline.
- Deployment strategy.

Do not deploy or modify cloud resources during this review.

## Step 6 — Final Coordination Report

Return a single structured engineering report.

Use this format:

# SIKA Engineering Review

## 1. Executive Summary

## 2. Critical Issues

## 3. High Priority Issues

## 4. Medium Priority Improvements

## 5. Low Priority Improvements

## 6. UI/UX Recommendations

## 7. QA Recommendations

## 8. Security Recommendations

## 9. DevOps Recommendations

## 10. Recommended Implementation Roadmap

Organize the roadmap in phases:

### Phase 1 — Critical
### Phase 2 — High Priority
### Phase 3 — Product Improvement
### Phase 4 — Optimization

IMPORTANT:

Do not modify any code during this workflow.

The goal is analysis, prioritization and planning only.
